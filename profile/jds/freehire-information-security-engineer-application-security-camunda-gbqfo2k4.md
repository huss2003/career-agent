**About the Role:**

Hi there! We're hiring an Information Security Engineer with a focus on Application Security to join our Information Security team at Camunda.

We are a team that takes security seriously without making it feel like a locked door. We work in a transparent, straightforward way, and we care about doing the work right rather than just checking a compliance box.

You will work side by side with our R&D engineers: reviewing designs, threat modeling new features, digging into code and helping teams make good, risk-based decisions about the vulnerabilities that come in. You'll also help build the internal tools that make this work scale, including our CVE registry and the LLM-assisted workflows we use to analyse code and triage findings.

Camunda is an AI-first company, and InfoSec is no exception: AI agents are part of how we review code, assess vulnerabilities, and build our tools. You will help shape how that works.

This is a hands-on role for someone who already has solid AppSec foundations and wants to grow. We are a generalist team, so you will also take part in our on-call rotation and incident response, and get exposure to other areas of security. But most of your time will be spent with engineers and building and maintaining internal tools and processes.

**What You Will Do**

- **Vulnerability management**: triage findings from SCA, container and code scanning, external reports and internal security testing; assess whether Camunda is actually affected; agree fix / mitigate / accept with engineering and follow through to release.
- **Threat modeling and security reviews**: run threat modeling sessions and design reviews with R&D teams for new features and architecture changes, and turn the results into concrete, prioritised actions.
- **Code analysis with LLMs**: use and improve LLM-assisted tooling (agents, prompts, reusable skills) to review code, validate findings and reproduce issues, while applying your own judgement to know when the model is wrong.
- **Build internal security tooling**: contribute to the CVE registry and related automation that connects scanners, engineering teams, and customer communication. Much of it is built on Camunda itself.
- **Help engineers do the secure thing by default**: answer questions, review pull requests, improve guidelines and occasionally run a session or workshop.
- **On-call and incident response**: share the InfoSec on-call rotation with the other engineers and help investigate and resolve security incidents.
- **Support the wider team**: help write security advisories for our customers, answer customer security questions and support audits.

**What You Will Bring to the Role**

- Around **3+ years in security or software engineering**, with at least 2 of them working on application or product security (AppSec, product security, pentesting, or a security-focused developer role all count).
- **Experience at a SaaS or software product company**, working closely with engineering teams that ship often through modern CI/CD and cloud environments.
- **Hands-on vulnerability triage**: you've worked with tools like Snyk, Trivy, Semgrep, CodeQL or similar, can tell a real issue from a false positive, and can explain how exploitable something actually is in context (CVSS, exploitability, configuration).
- **Threat modeling and design review** experience (e.g. STRIDE) on real systems, ideally web apps, APIs, or distributed services.
- **You read and write code.** You're comfortable reading Java (Camunda is built on it) well enough to follow a data flow and spot a security bug. You can write scripts and small tools and contribute to an existing codebase with review.
- **You build with AI, not just chat with it.** You use AI coding agents (Claude Code, Cursor, Copilot or similar) in your daily work to write tools, analyse code or automate tasks. And you know their output still needs a second look, especially when it comes to security.
- **Clear, friendly communication** with engineers. You see yourself as an enabler, not a gatekeeper, and you can explain risk to people who aren't security specialists.

**Nice to haves**

- Some Python and/or JavaScript experience, or experience building internal tools.
- Willingness to learn and use Camunda, since we build a lot of our own security automation on it. Prior BPMN / workflow experience is a plus.
- Experience responding to security incidents or being part of an on-call rotation.
- Exposure to security advisories, CVE disclosure or bug bounty programmes.
- Knowledge of AI/LLM security risks (OWASP Top 10 for LLMs / agentic apps, prompt injection, tool abuse).
- Experience securing Kubernetes or container-based workloads, or open-source / B2B software.
